Nakoa

Un videojuego multijugador hecho en Unity con un objetivo claro: que el mismo juego funcione en el móvil, en el ordenador y en el navegador. Un único proyecto en C# que se compila para Android, iOS, PC y WebGL.

Contexto

La idea era que cada jugador eligiera dónde jugar: en el móvil, en el ordenador o en el navegador, sin instalar nada. Nakoa partió de esa premisa: no hacer cuatro juegos, sino uno solo que se compile para cada dispositivo y se juegue igual de bien en todos.

Qué hice

  • Desarrollé el juego en Unity con C#, como un único proyecto preparado para compilarse en Android, iOS, PC y WebGL.
  • Separé lo común de lo que depende del dispositivo: escenas, lógica y recursos se comparten, y la entrada y la interfaz se adaptan a cada plataforma.
  • Publiqué una build WebGL en GitHub Pages como demo jugable: corre en el navegador con WebAssembly, sobre WebGL 2 y con WebGL 1 de respaldo.
  • Desactivé el multijugador en la demo web y dejé el proyecto completo fuera de GitHub por su tamaño; lo facilito por correo a quien lo pida.

Arquitectura

Un proyecto y cuatro salidas. El pipeline de build de Unity genera una versión por destino a partir del mismo código; la de WebGL se publica como web estática y es la única que prescinde del multijugador.

  1. Un único proyecto de Unity: escenas, lógica en C# y recursos, comunes a todas las plataformas.
  2. La entrada y la interfaz se adaptan al dispositivo, para que el juego se sienta propio en cada uno.
  3. El pipeline de build de Unity genera una versión para cada destino: Android, iOS, PC con Windows, macOS y Linux, y WebGL.
  4. La build WebGL corre en el navegador con WebAssembly y se publica en GitHub Pages, sin el multijugador.

Qué aprendí

Que multiplataforma no es pulsar «Build» cuatro veces. Cada destino pone sus límites, y el navegador es el más estricto: hay que decidir pronto qué es común y qué depende del dispositivo, y aceptar que la demo web no puede hacerlo todo.
